# L3 反例 · 05 取料（A-01..A-03 · A-17 · A-19 · A-21）

> 反例 = **真实发生过的失效**，带实测数字 + 日期 + 可指的出处。数字会漂（外源 / 快照类材料只引方法、不引结论）—— 本册的数字只作「当时的观测」，不作当前承诺。
> 每条四段：**现象** / **根因** / **正解（指向 P-NN）** / **怎么早发现**。
> 反例比正面陈述信息量大：正面写「应该怎样」容易被读成口号，反例写「怎么坏过」才有判据。

## A-01 冷启动「余量还有」是假象

- **现象**（另一项目 2026-09-16 ~ 10-24 至少十次拆分；2026-11-03 复核）：一个文档家族切到 **21 卷 / 387,337 B（约 378 KiB）**；路由页 **30,374 B**，其 symbols 索引 **35,914 B** —— 比它索引的 10 个子卷**全部**都大（最大子卷 **25,041 B**；均为字节，同单位）；出现「早期分卷」当垃圾桶（按领域切完没处放的内容）；家族唯一的有效性闸「信息完整性抽检」**长期 0 次执行**（2026-11-02 才首次执行：三问全过 + 当日复测）；源仓多份文档的分卷触发点贴着读取上限（41,621 / 48,165 / 49,469 / 49,165 / 50,197 B；**分属不同家族**）。
- **根因**：冷启动字节的**测量对象会变**（第一读换了，总量就换），而记录只在收尾写一次。「余量还有」被当成**状态**，它其实是**一次快照**；写进文档后没有任何机制会重测它。
- **正解**：P-01 —— 余量不足即**立即归档**，不写「还有」；字节数当**命令输出**引用，不当**文档结论**引用。
- **怎么早发现**：任何「余量 / 剩余 / 还有」措辞都问一句「谁重测它」；答不出 = 它明天就会是错的。

## A-02 查询型文档没有硬顶 = 无限叠加

- **现象**（2026-10-29 实测，另一项目）：一份 `open-items` 台账 **246.7 KB**，旧门禁只出一条 `WARN` 就通过；OPEN 与 CLOSED 混排在同一文件里，想归档得先写脚本才能分出「已收口」的部分。
- **根因**：两档模型里查询型（清单 / 台账这类只增不减的文件）「>50 KiB WARN、>100 KiB **也只 WARN**」—— 体积上限被默认成整读型的专属，查询型成了**豁免区**；而它恰恰是增长最快的一类（append-only 台账）。
- **正解**：P-03（四档 + 硬顶只适用 A/B/C，前提是 D 档真的是「逐字归档」而不是「累积台账」）+ P-05（配额制，到顶先合并）。
- **怎么早发现**：先判档（这个文件属于哪一档），再问「**它的硬顶在哪**」；答案是「没有」就当场登记债，别等它长到 200 KB。

## A-03 探针「只在声明了才校验」

- **现象**：按节读探针**存在**，但只在文件**自己声明了**才校验 —— 声明是自愿的，于是**最大的文件往往正是没声明的那个**，探针一路绿。
- **根因**：「登记式校验」把「没登记」当成「不适用」；探针的覆盖面由**被检对象自己**决定 → 结构性漏报。门禁读的是**路径/声明**，不是**类**（同族：写死单路径 → 分卷后探针面静默变窄）。
- **正解**：P-04 —— 超阈**必须**声明，由探针**反向强制**（缺声明 = `FAIL`，不是「跳过」）。
- **怎么早发现**：对每个探针问一句「**它靠什么保证该检的都被检到**」；答案是「文件里写了才查」= 有洞。

## A-17 照字面 copy 模板 = 死指针；能躲开全靠执行者越权改写

- **现象**（2026-11-01 实测，一次真实接入）：模板的指针按**上游项目形状**写死（形如 `<真源目录>/session-workflow.md`），而目标项目里没有那些文件；执行者**没有照做 copy，而是自己把它改成 merge**，才让实录里的死指针停在 0。→ 这次实测证明的是「**协议照字面执行会产死指针、能通过只因为执行者越权**」，**不是**「它装出了一整套死指针」。同一轮另有一条同类但更具体的：验收清单 §4 的命令在没装门的项目上直接是空指针。
- **根因**：模板是**上游项目形状**的骨架（占位符 + 指向上游项目的路径），而协议只给了「copy」这个**动词**，没给「拷完算完」的**完成条件** —— 正确性于是落在执行者的自觉上：自觉的越权改成 merge（协议说的是 copy），不自觉的交付死指针。两种都不报错。
- **正解**：`P-26` —— 本条的**病**就是「照抄完没有完成条件」，`P-26` 把它变成「裁到 0 处」的动作 + 判据；动作落点 = `skills/coldstart-intake` 第 1 步，判据 = `kit/scripts/trim-scan.mjs`（占位符 0 处 · 死指针 0 处）。**分工**：`P-26` 管「**多带**」方向（照抄来的行要裁掉）；**`P-28` 管「少带 / 变形」方向**（copy 件被重裁：原样 / 改造 / 新增 / 丢失四类点数，**丢失必须写理由** —— D-4 是它的第二个实例）；本条只负责记「不裁会怎样」。
- **怎么早发现**：交付前跑一次 trim-scan，问「**两处计数是不是都 0**」；更快的问句 = 随便抽三行指向的文件，打开它 —— 打不开就是没裁完。
## A-19 协议只写「读开头 30 行」，而它要的证据在文件后半 —— 靠执行者违规才没漏判

- **现象**（2026-11-02 盲测实测，**近失** —— 不是已发生的漏判，是「靠执行者违规才没漏」）：`skills/fit-kit/SKILL.md` §1.3 原写「每份读开头 30 行」；目标仓一份 312 行的分类索引里，**失效证据在 :276**（表头写 16 条 / 2026-07-14，正文实为 17 条、末条来源日期 2026-07-17；行号以该仓为准）。被测 agent **违反协议**去整读了 312 行，所以它没漏判 —— 换一个守协议的执行者，结论就会是「没有失效」。**真正的失效物 = 协议里的读法本身**（它保证不了结论所需的那一段）。出处 = 当轮决策记录 §13 卡点 ④。
- **根因**：把「读了一点」当成「读够了」—— 截断点由**成本**（30 行、一屏、一次工具调用）决定，不由**判据需要**（失效可能在最后一节、最后一个表头）决定；两者在文本上一模一样，看不出谁对。
- **正解**：`P-30`（引用内容 ⇒ 拿得出覆盖记录）+ `P-04`（按节读：先抽 `##`，再只读相关节）。动作落点 = 任何「读文件给结论」的协议里写**读法**，不写行数。
- **怎么早发现**：写「我读了 X」时问一句「我读的是**它的哪一段**，判据需要的是**哪一段**」——两段不重合 = 还没读。

## A-21 按量拆卷：路由页自己长成最大卷，有效性闸长期空转

- **现象**（另一项目 2026-09-16 ~ 10-21 四批搬家 + 2026-11-01 复核）：一个文档家族切到 **21 卷 / 376 KB**；路由页 **29.7 KB**，其 symbols 索引 **35.1 KB** —— 比它索引的 10 个子卷**全部**都大（35.1 KB vs 最大 25.0 KB；2026-11-02 复核）；出现「早期分卷」当垃圾桶（按领域切完没处放的内容）；家族唯一的有效性闸「信息完整性抽检」全仓只有 1 次定义 + 3 次改革记录、**0 次结果记录**；切分触发点贴着读取上限（41,621 / 48,165 / 49,469 / 49,165 / 50,197 B）。
- **根因**：切分单位是**原文的节号**（「这文件又到线了 → 把最大那节搬出去」），不是**读者 / 问题**；于是每次搬家都长出新的路由页 / 指针 / 探针面，路由页自己变成新的最大卷；而「拆完有没有丢信息」从未被验过 —— 失败不报警。
- **正解**：`P-32` —— 拆前先答四问（按节读够不够 / 是不是读不完 / 是不是两个读者 / 只是大）；只在第 2、3 问成立时拆、按读者切；路由页 ≤ 中位数、是第二书写点；拆是单向门。
- **怎么早发现**：每次拆分后问两句 —— ①「这次拆是为了哪一类读者少读？」答不出 = 为避线而拆；②「路由页是不是家族里最大那件？」是 = 索引已不是索引。
