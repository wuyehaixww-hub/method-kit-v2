「取」= 从本方法仓挑**一条判据**，治项目里**一个具体失效**。它不是「装」：不建治理面、不搬整套、不建第二套分类学。

产出 = **一份决定**（取 / 不取 / 只取一支），不是一个模子。**不取也是合格答案。**

## 第一闸：这是「取」吗（不是 → 去别处，别硬套）

| 情况 | 去哪 |
|---|---|
| 项目还没有体系（没文档、没规则、刚开工） | `skills/adopt-kit/SKILL.md`（**装**，不是取） |
| 有体系，但**说不出一个具体失效** | **不取**。配额 0 是合法答案（`P-05`）。**想先诊断出失效** → 回 `skills/fit-kit/SKILL.md`（它负责把「说不出」变成「说得出」，本文件不复制那套问题） |
| 只是「这条看起来有用 / 写得挺好」 | **不取**（过度采纳是取的头号风险） |
| 要改本方法仓的判据 | 本方法仓的 `add` 动作（那是改本方法仓，不是取） |

**进门判据**：能不能一句话说出「**谁在什么时刻会出错，错成什么样**」？说不出 = 停在这里，不要往下写。

## 六步

1. **痛点**：写下那个失效（一句话 + 一个可指的实例：文件 / 行 / 日期）。**没有实例 = 抽象采纳**，风险最高 —— 先不取。
2. **判据**：在本方法仓找一条治它的。按回退阶梯走（`P-02`）：场景路由 → 抽大纲 → 任务词 grep → 换词重试 → **报缺口**。找不到就登记，**不编一条**。
3. **相关性测试**（三步，缺一不可）：
   - **它已经有规则了吗**：项目已有规则**已经**治好这个失效 → **先修那条**，不取。理由不是「省事」，是**两条规则治同一件事 = 两个书写点**，改一处必漏（同 `A-06` 的形态）。
   - **替换测试**（`P-21`）：把本方法仓判据的「根因句」拿去替换项目已有规则的根因句 —— 不失真 = 同一条，不取。
   - **它有实例吗**：项目里找得到发生过的实例吗？找不到 → 降级成「观察项」，不取。
   - **面要枚举**（`P-14`）：说「本项目只有这一处」之前，先 `grep` 一遍**同形**（同字段 / 同句式的表头行）—— 只在一个文件里看到 = **样本**，不是**面**；没打开的候选要在记录里点名（「未证实」比「没有」诚实）。
4. **适配**：只搬**义务**，不搬**词**。
   - 用项目自己的话写规则；要引出处就写一行「依据：method-kit `P-25`」，**不把编号铺进正文**。
   - **降级到项目付得起的规模**：一条判据 + 一个检查 + 一个复审日。本方法仓一条判据可能有六个检查点，项目只需要其中一个 —— 取那一个。
   - **能删就不加**：如果「删掉那个会漂的计数 / 把它降级成指针」也能治，优先删（同一条判据的降级分支）。
   - **删位还是同步**：先读那一行是**断言当前**（「包含 N 条」「最后更新：2026-07-14」）还是**明确标了观测时点**（「截至 X，共 N 条」）。**断言当前 = 会漂 → 删 / 降级成指针**；标了时点的 = 当时观测 → 同步或改成时点句。判据：一个三个月后的读者会把它读成「现在」还是「当时」。**注意**：`最后更新：<日期>` 是**断言当前**（它说「最后改于 X」，一改就错），不是时点标注 —— 这类日期行同样走「删」。
5. **最小试点**：**先写预测再动手** —— 「如果这条生效，下周应看到什么」。范围 = 一个文件 / 一次改动，不做全项目推广。
6. **复审**：定日子，到点问三句：还成立吗 / 抓到过东西吗 / 该撤吗。**没复审 = 没取**（三个月后它会变成仪式）。
   **日子按改动频率定**：高频（每周都有改动）→ 一周；**低频**（上次改动 > 1 个月）→ 定在「下一次同类改动」，并补一句「若 X 月内无同类改动 = 试点无数据，按撤销处理」。判据：复审必须能**证伪** —— 在一个不会发生事的仓库里定一周复审，只能得到「什么都没发生」。

## 三条硬纪律

- **说不出失效 → 不取**。宁可这次不取，也别让项目多一套没人执行的仪式。
- **一次一条**：上一条没复审，不取第二条（配额制，`P-05`）。
- **没有撤销路径 → 不取**：第 6 段写清「怎么撤、撤的代价」。撤不掉的采纳是单向门。

## 取的时候不能做什么

- **不搬判据正文**：抄规则不抄失效 = cargo cult（读者学到语气，学不到判据）。
- **不改项目的分类学**：把 `P-NN` / `A-NN` 体系搬进项目 = 第二套 taxonomy（三条术语规则与可 grep 判据 = `skills/adopt-kit/SKILL.md` §术语校准，本文件不重写）。
- **不当「装」用**：取不建治理面；要建 → `adopt-kit`。
- **不替项目拍板**：「收不收」是价值判断（本方法仓的分权判据）—— 你给成本、后果、撤销路径，它自己选。

## 记录（六段；一次取一份）

**六步与六段不是一一对应**（别按编号硬配）：§1 痛点 ← ①；§2 相关性测试 ← ②「判据」+ ③；§3 决定 = ③ 的产出（取 / 不取 / 取哪一支）；§4 适配 ← ④；§5 试点 ← ⑤（复审日也写这里）。**§6 撤销路径 = 做 ③ 决定时就要写的东西**，不是试点之后再补。**⑥ 复审没有独立段** —— 它是到点执行的动作，结果回写 §5 的「预测」旁边。

```markdown
# 取：<项目> · <判据编号> / <一句话>

- 日期 / 项目 / 取证基线（commit）

1. **痛点**：<谁在什么时刻会出错，错成什么样> —— 实例：<文件:行 / 日期>
2. **相关性测试**：已有规则 = <有/无 + 指哪>；替换测试 = <能/不能替换，为什么>；实例 = <有/无>
3. **决定**：<取 / 不取 / 只取哪一支> —— 一句理由
4. **适配**：<改写成项目自己的话；降到哪一处；删掉了什么>
5. **试点**：范围 = <一个文件 / 一次改动>；预测 = <如果生效，一周后应看到什么>；复审日 = <YYYY-MM-DD>
6. **撤销路径**：<怎么撤；撤的代价>
```

落点：**项目的**记录区（不要写进本包；本包不承载你的取料记录）。

## 反例（都真实发生过；每条带一个可打开的落点）

- **面只看到一处就下结论**：2026-10-31 的试跑里，作者先在 1 个文件看到 2 处摘要行，`grep` 全库后实为 **3 处 / 2 文件**（一次只读试跑；同一场里数字要重算）。
- **把编号铺进项目文档** → 项目里长出第二套分类学：同一次试跑的产物被要求「正文不出现 `P-\d+`」，`grep` 复核 0 命中才算过（历史试跑；同一场里复核 0 命中）。
- **只抄规则句、不抄「它防的是哪种坏结果」** → 半年后没人知道这条为什么在；本方法仓自己的处置 = 适配段必须写「删掉了什么」（历史试跑）。
- **试点只写「应该会有帮助」、不写预测** → 复审时无法证伪；本方法仓的处置 = 第 5 步强制写「预测 + 复审日」（历史试跑）。

## 不做

- 不替项目决定收不收（给成本与撤销路径即可）。
- 不在这里复制 `principles/` 的正文（判据真源在那里，这里只给步骤与指针）。
- 不重做 `adopt-kit` 的 7 问（那是「装」的 grill）。
- 不写「建议 / 尽量」：要么是一条判据 + 一个检查 + 一个复审日，要么不取。
