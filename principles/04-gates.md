# L0 原则 · 04 门禁（结论 / 会咬 / 断言 / 面 / 边界）

> 本册 = 「**一条门禁凭什么可信**」。5 条：P-11..P-15。
> **阈值不写在本册**（真源 = `kit.config.json`）；**动作清单也不写在本册**（跑什么、什么时候跑：按 `kit/templates/CLOSEOUT.md.template` 自建）。本册只写**判据**。
> 与邻近册的分工：**怎么用门禁查文档** = 05 册（P-01..P-05）；**结论怎么可证伪 / 复核怎么换判据** = P-10；**本册** = 门禁给出的那句话本身凭什么成立。
> 每条四段：**规则** / **为什么** / **反例** / **怎么查**；`怎么查` 没有机械点就诚实写「半机械」，不假装有门禁。

## P-11 门禁的结论只来自「判定行 + 它自己的退出码」


- **规则**：读一次门禁运行，只认两样东西 —— ① **判定行**（脚本自己打出的 `FAIL` / `WARN` / 「未通过」**明细**；它可能在输出的**任意位置**）；② **脚本自己的退出码**（三态：`0` 通过 / `1` 门禁红 / `2` 环境错误；约定真源 = `README.md` §兼容承诺 3）。三条禁令：**不得只看最后几行**（明细常与 `N FAIL` 汇总行分散在前后，汇总行不能当明细）；**不得用外层转述的码**（工具回传值 / 命令链最后一条的码 / CI 的「成功」）；**不得把 `2` 当红** —— 它修的是环境，不是文档。（**与 P-10 的分工**：P-10 的「数字贴命令尾行」是**取数**口径 —— 贴的是那个数字所在的行；本条禁止的是**用最后几行判红绿**，两回事。）**外层只剩一个 `1` 时**（工具把 `2` 折叠成 `1`）按顺序裁决：① 有 `FAIL` 明细 → 红；② 有「退出码 2 = 环境错误」话术 → 环境错误（修环境，不是改文档）；③ 两者都没有 → 按**未捕获异常 / 被杀**处理（看栈），既别当红、也别当绿。另：`WARN` **不阻断** —— 它只是提醒；要它真拦住，就得有机械强制点，否则必须承认它拦不住（例：`cold-start` 的余量 WARN 不阻断，而 A-01 正是「跌破强制归档线没人发现」—— 这类只能配 P-15 的固定时点问句，或把门禁改成 `FAIL`（改验收面，另议））。
- **为什么**：门禁有两个输出层 —— **给人读的判定行**与**给机器判的退出码**。只看末几行 = 只取输出形状；信转述 = 只取别人概括的码。两者都绕开了唯一能否决的信号，而且**失败是静默的**：读成绿之后，红会随提交进历史（A-07）；反过来，把 `1` 一律当红，会把环境错误（`2` 被折叠）和崩溃（无判定行）也记成「文档不合格」，人开始不信门禁。
- **反例**：A-07 · A-16（门量错了对象，还给你绿灯 —— 判定行与退出码都对，对象不对）。
- **怎么查**：**半机械** —— 脚本侧有码（`process.exit` 三态 + 头注释声明），**读法侧没有探针**。人工等价：① 先取**那次运行自己**的退出码（`$LASTEXITCODE` / `execFileSync` 的 `status`，不信工具回传值）；② 非 `0` 再取明细 `node kit/scripts/check-kit.mjs 2>&1 | Select-String '^\[check-kit\] (FAIL|WARN)'` —— **不要**用 `Select-String "FAIL|WARN"`：绿跑的汇总行 `0 FAIL / 0 WARN` 也会命中（实测 2026-10-31）；③ 两者不来自**同一次**运行就不算证据。

## P-12 会咬 = 可复跑的注入态，不是一次观测


- **规则**：一条探针「会咬」的证明 = **可复跑的态**：注入违例 → 该探针红 → 复原 → 绿。四个要素缺一不可 —— ① **配方**（怎么注入；写进脚本头部注释，别人照着能复现）；② **态**（进 `selftest`；下一棒一条命令复跑）；③ **隔离**（关掉该探针 → 该态变绿；判据与方法 = P-10「怎么查」，此处不复述；**做不到就合并或记账**，不假装有证明）；④ **同改**（改判据或改扫描面，必须同一次提交里改配方与态）。一次性手工注入、贴一张红的截图、整套全绿 —— **都不算**（A-09）。
- **态的形态（一个态只能证明「它能咬」）**：注入态必须覆盖三种形态 —— ① **输入在、内容错**；② **输入不在**（删掉载体 / 缺配置 / 空集合）；③ **身份指错**（从多个候选里挑错了对象）。只做 ① 证明的是「探针会咬」，**不证明「它在真实态会咬」**；缺 ②③ 的探针会在生产上**静默空转**，而它对外报的仍是绿。**2026-11-02 实例（跨仓）**：上游项目一条新探针按 `mtime` 挑「最新 handoff」→ 挑错文件（差 10 秒）、载体里没有要读的那行、缺行时直接跳过不报，三条叠加 ⇒ 从上线到被发现**一次都没执行过**，门禁一直 0 FAIL。这是「假绿」的第二种形态：不是探针不咬，是**探针根本没跑**。
- **为什么**：证明的价值不在这一次红，在「**下一次还能红**」。手工注入是当轮观测，会随会话消失；门禁改动最典型的失效不是改错，是**改完再没人验证过它还会红**，于是一条已经不咬的探针继续发绿灯。
- **反例**：A-09（手工注入 / 贴截图）。**空转型**：A-25（参照参数指错 → 禁止集为空 → 门报绿；本方法仓 2026-11-07 首个亲历实例）。
- **怎么查**：`node kit/scripts/selftest.mjs`（每态 = 一条注入；全 PASS 只说明「整套里还有探针会咬」）。**新增 / 改动探针时**：把态写进 `CASES`，并做一次隔离对照 —— **方法与贴尾行的要求不复述，见 P-10「怎么查」与收尾清单第 3 步**。**三态覆盖现状**：`selftest` 现有态里 ① = **每个探针至少一态**（态数 = `selftest` 尾行「全部 N 项」，本册不写死数字）、② 有（`coldstart-missing` / `no-config` / `evidence-required` 等），③ **身份指错无态** —— 已登记留后登记面 §5（不假装已覆盖，`P-15`）。

## P-13 断言值必须从当前状态推导


- **规则**：注入态与校验里出现的每个值，只有两种合法来源 —— ① **从当前状态读出来再变形**（读当前版本号 → 追加 `-mismatch`；按 `coldStart.limitBytes` 减去已用字节算补白）；② **配置里的阈值**（`kit.config.json`，唯一书写点）。**禁止**把「我测的时候是多少」写成常量 —— 版本号、字节数、条数、**会变的编号**（如「下一个空号」）、行号（会随内容漂的那种）都属此列。**不算观测值的**：契约固定的 ID（`P-NN` 不重排、不复用）与**高于配额上限的死号**可以写字面量 —— 判据仍是那一句：**这个值会随项目演进而变吗？会变 → 它就不能以字面量出现。**
- **为什么**：写死观测的测试**只在写它的那天正确**。之后要么「恰好一致」而假绿（期望红、实得绿 → 门禁失去意义），要么「对象长大了」而误报（红在无关处 → 人开始忽略门禁）。两种失败都不报错，只在下一次真实改动时暴露（A-08）。
- **反例**：A-08。
- **怎么查**：**半机械** —— 没有探针能判「这个字面量是不是观测值」。人工：对每条注入态问「把项目升一版、把文档加长 10%，这条还成立吗？」；机械辅助：`grep` 断言里出现的版本号形（三段数字加点）、以 `B` 结尾的整数、编号形。**例外**：确实需要字面量的地方（如补白的重复字符数），必须由阈值或当前值**算出来**，并在注释里写算式。

## P-14 面从全集来；一切缩面都是欠账


- **规则**：一条门禁的**面** = 由查询得到的**全集**（`git ls-files` / `readdir` / glob）**减**显式缩面。先分清两件事：**对象定义**（例：只扫 `.md`、跳过 `.git` / `node_modules`）写在脚本一处即可，它**不是**缩面；**缩面**是「本该进面却被跳过」，必须登记。允许的缩面只有三种：① **定义性豁免**（例：P-03 的 D 档逐字归档 —— 路径与节号反映「当时」）**不需要到期动作**，但必须**写在规则里且可枚举**（它是「对象定义」，不是债）；② **过渡性冻结**（存量先冻结、只判新增 / 变大）与 ③ **白名单 / 例外**（每条带理由）则必须**可枚举 + 带理由 + 有到期动作**（冻结是**欠账登记**不是「合法」；白名单配**过期自检**：命中不掉即报红，逼同步删除）。另有一条顺序：**先把对象改到位，再收紧线** —— 否则新线一上线即红，人只能加白名单续命。
- **为什么**：面的默认状态是**漏**，不是全。清单不随新文件增长；白名单不随代码收敛；冻结名单不随存量清理。三者都不报错，只让绿灯越来越便宜（A-09）。本方法仓的冻结还窄一层：放过判据是「**大小不增**」（`check-kit` 的 `frozenOf`）—— 一旦冻结，**整条文件**（含行数 / 单行长度）与探针 7 都跳过：把两段文字换成一个 4000 字符长行、总字节不增，也能全绿。所以冻结只能是**过渡**，到期必须清或换成内容判据。
- **反例**：A-03（同族第一条：探针只查「声明过」的对象）。
- **怎么查**：**半机械** —— 面可以从代码读（`walk` / `git ls-files` / `tierOf` / 白名单常量 / `--baseline` 文件）；「缩面是否都登记了」没有探针。人工：对每一处缩面问三句 —— **谁划的 / 理由是什么 / 到期怎么清**；机械辅助：缩面必须有唯一落点（`kit.config.json` 的 `pathRoots` · `tiersByDir` · 冻结文件名）；**对象定义**（扩展名 / 排除目录）同理只有一个落点（脚本的 `walk`）。

## P-15 门禁只覆盖可机械判定的那一类


- **规则**：给一条失效找门禁之前，先问「**期望值机械可得吗**」—— 能不能写成「对某个可计算对象求值 → 与**一个机械可得的期望**比较」？能 → 走 P-14，把面做全（例：搬运丢条目 = 搬前 / 搬后**数条数**；版本漂移 = 探针 6 的 `VERSION ↔ CHANGELOG` 顶部）。不能（**宣称与事实不一致** / **摘要与正文漂移** / **两条口径谁对** —— 期望要靠人读语义或做价值判断）→ **不要加探针**，写成固定时点问句（时点与问句 = 收尾时的四类机械自查，本册不复述）。加检查也只解决「发现两处不一致」，不解决「该保留哪一处」—— 先修源头（唯一化）再考虑加检查（同义判据 = 每条判据要答的**四问**：判什么 / 证据在哪 / 不做会怎样 / 怎么查 —— `GUIDE.md` §十 有这四问，本册不复述）。
- **为什么**：把语义类失效硬塞进门禁，会得到两样东西：一条判据靠人肉解释的探针，和一份更长的绿名单（人更放心）。而这类失效恰恰**不报错** —— 文件在、格式对、门禁绿（A-04：三处版本各说各的，而门禁全绿），只能在它变成事实之前用问句拦住。
- **反例**：A-04（状态真源没写回 —— 版本号可 grep，但「进度 / 第一读 / 留后项写没写」没有机械签名）· A-23（门绿 ≠ 这条做完了：主张的面大于门的面）。
- **怎么查**：**半机械** —— 机械点只到「门禁是否全绿」；「该不该加这条探针」靠人判。人工等价：先问「**期望值从哪来**」—— 答不出一个可查询的真源 = 它没有机械签名；再写出这条失效的**反例**（带日期与实测）。
