# L3 反例 · 03 交接（A-10..A-12）

> 反例 = **真实发生过的失效**，带实测数字 + 日期 + 出处。数字会漂 —— 本册的数字只作「当时的观测」，不作当前承诺。
> 每条四段：**现象** / **根因** / **正解（指向 P-NN）** / **怎么早发现**。
> 选条标准：**三个不同根因各一条**，不把一个根因写成三条（否则反例册变成同义反复）。

## A-10 指针落到了另一个物：局部编号被当全局 ID / 一物两名

- **现象**（本方法仓 2026-10-31 同一轮收尾的两处实测）：① **局部编号被跨件引用** —— `D6` / `D7` 在**上一份记录** §6 里分别指**接入矩阵**与**同步基线**，在**这一份记录** §6 里**正好相反**；上一棒的 handoff 按编号引「D6」→ 读者按号找到的是**另一笔欠账**（复核 R-6 实测；两件各自都「读得通」）。② **一物两名** —— L1 骨架的同一件在台账里叫 `hook`、在 handoff 里叫 `handoff` 模板，两处各写一份进度 → 读者以为是两件（R-7；处置 = 统一为台账的 canonical 名）。
- **根因**：**编号与名字是局部产物，引用是全局行为**。每件都从 1 重新起号、每个作者各自起名 —— 于是同一个 `D-6` 在两件里是两件事，同一件事又可能有两个名字。而解析**不会报错**：编号存在、名字存在，只是**指着别处**。这比「指不到」更贵：A-12 是**找不到**，本条是**找到了错的那个** —— 读者会自信地做错事。
- **正解**：**P-16**（把副本换成指针的前提 = 指针必须落到**唯一实体**：跨件引用写**名字**或**全局唯一 ID**；只在本件内有效的编号，就地声明作用域）+ **P-09**（改名 / 迁移时三形反查）。
- **怎么早发现**：写任何跨件引用前问「**这个编号在别的件里是不是指别的事**」—— 答「可能是」就写名字；改名前 `grep` 三形（全名 / 目录前缀 / 旧措辞）。读者侧：看到一个编号，先在件内找「编号作用域」的声明；没有声明 = 按全局读必错。

## A-11 把「计划」当「现状」、把「转述」当「事实」

- **现象**（两处实测，同一根因）：① **本方法仓 2026-10-31**（一次收尾前）：handoff §0 写 tag = `v0.4.0-dev`，而 `git tag --list` 里**没有它** —— tag 要等收尾的「归档与版本」那一步（提交 → 打 tag）之后才打；同节还写「HEAD = 应为收尾提交」—— **这句至今仍在原件里**（当轮只改了 tag 那半），本条的**第一个待改样本就是它自己**（复核 R-1）。② **另一项目 2026-09-21**：上一棒 handoff 的 §3/§7 两处把分区转述成 `cards.partition`，实际 `partition` 是 `Decks` 表的列（`Cards` 表只有 `id/deckId/sortOrder/wordData/createdAt`）。**原件当天已就地等长订正、原文不可复现**；该文件还被 `.gitignore` 忽略（**本机未跟踪**）—— 所以这里只引那份判定记录的**编号**，不复述那两行原文。两份活文档同错，**没有门禁能校验文本与 schema 一致**。
- **根因**：交接件的作者站在**计划**里，读者站在**现状**里 —— 中间隔着一整个收尾；而文本与原件之间**没有门禁**。于是「我会做 X」与「X 已做完」、「上一棒的转述」与「原件」在文件形态上**长得一模一样**，读者只能靠作者的记忆与诚实。
- **正解**：P-17（每个「是什么」指回原件或给判据；禁结论性事实与期望值）。
- **怎么早发现**：把交接件里每个「是 / 已 / 应为 / 还有」圈出来，逐个问「**下一棒用哪条命令能自己算出来**」；答不出 = 它是断言，不是判据。转述类再加一问：「我在**本会话**里打开过原件吗？」

## A-12 必读清单从未被解析

- **现象**（两处实测）：① **本方法仓 2026-10-31**：handoff 必读清单第 8 条写「某文件 §8.6」，而那份文件只有 **§0–§4 附**（§8.6 在**另一个文件**里）；复核 R-3 抓出。下一棒照读会在**第一个文件**里找不到 —— 正好触发「没找到 ≠ 不存在」的自创风险。② **另一项目 2026-09-13**：`item-brief` 初稿把上游源件与台账写进反引号（**契约真源映射表**里的指针）—— 那些目录被 `.gitignore` 忽略，本机存在、`check-docs` 查的是**本机文件系统**所以全绿，换机 / CI 克隆后不存在（该条记录的实测：tracked 侧 **41 文件 / 155 处**）。**注意那时观测的对象是「契约真源映射表」，不是 handoff 必读清单** —— 本条引它的是「指针要能跨机解析」这条判据，不是「清单出过事」这个事实。
- **根因**：清单由**写的人自证**（他写的时候文件在、在他机器上、节号是对的），却由**读的人第一次执行**。况且「路径存在」与「节号存在」是两件事 —— 后者本方法仓无探针。清单错了**不会有任何门禁变红**，只会让下一棒在第一步撞墙。
- **正解**：P-18（每条带「为什么」+ 开工第一步逐行解析 + 只指已跟踪锚点 + 跳过要写明）。
- **怎么早发现**：开工第一件事 = **逐行打开清单**，确认文件在、节号在；任何一行打不开，**当场报缺口**（别绕、别猜、别自创）。写的人侧同理：写完清单**自己按清单走一遍** —— 下一个用它的人不是你。
