# L3 反例 · 07 反例（A-13..A-15）

> 反例 = **真实发生过的失效**，带实测数字 + 日期 + 出处。数字会漂 —— 本册的数字只作「当时的观测」，不作当前承诺（`P-24`：引编号 / 记录 / 节标题，不引「当时那句话」）。
> 每条四段：**现象** / **根因** / **正解（指向 P-NN，不抄规则）** / **怎么早发现**（`P-23`）。
> 选条标准：**三个不同根因各一条**，不把一个根因写成三条（否则反例册变成同义反复）；「不同」怎么判 = `P-21` 的替换测试。
> 本册三条各站一个时刻：**立条时**（A-14 撞根因）· **取证时**（A-15 引文会消失）· **改正文之后**（A-13 摘要停在旧口径）。

## A-13 摘要与正文漂移（标题 / 表头 / 索引行 / 地图行说旧口径，正文已改）

- **现象**（本方法仓两处实测）：
  ① **2026-10-30**：`principles/02-closeout.md` 的 **P-08 标题与引言仍是旧口径**（正文已改成「两个触发」，标题还说「只认收口」）—— 复核第三轮 #1 抓出；同一轮改动的 `README.md` 地图 P-08 行漏了「真机窗口」。两处都是复核第三轮 **#1** 抓出的，当时落账为候选反例「摘要与正文漂移」（**D12**）。
  ② **2026-10-31**（收尾复核 **R-6**）：索引新增行写「自审 **R1–R14** / **D1–D9**」，实为 R1–R19 / D1–D10；相邻那行还写「前几棒都 ✅」。出处 = 复核 **R-6**。
- **根因**：摘要（标题 / 引言 / 表头 / 索引行 / 地图行）是正文的**有损导数**，在写入那一刻生成；之后正文改了什么，它**收不到任何信号**。**与 A-06 不是一回事**：A-06 是同一粒度的两份副本（按定义应当逐字相等，改一处漏一处）；本条是**两个粒度**（一份正文 + 一份对它的压缩），压缩在前、正文改在后，二者的义务关系从来没有被写下来 —— 于是「改正文的人」不觉得自己欠摘要一次回改。最贵的是**顺序**：读者先读标题 / 表头 / 地图行，再读正文 → 旧口径先入为主，他拿它去读新正文，甚至会反过来怀疑正文。**与 A-01 的替换测试**：A-01 的载体是**测量值**（被测对象自己会变 + 只测过一次），本条是**正文的压缩**（对象没变、正文改了而摘要没跟）—— 两句根因不能互换：把正文改对、摘要不动，A-01 的根因解释不了它。
- **正解**：**P-25** + **P-06**。**动作**：改正文的同一轮，把该文件的摘要位同改、或降级为纯指针（别留会变的口径 / 数字 / 范围）。**分工**：P-06 管**副本**（同一事实两处写全，按定义应当逐字相等）；本条是**两个粒度**（正文 + 它的压缩）之间的债 —— 别把它当 P-06 的实例。
- **怎么早发现**：改完正文，**回读该文件的摘要位**（标题 / 引言 / 表格表头 / 索引行 / 地图行 / 册首的条目区间），逐句问「**这一句是不是在替正文说话**？」—— 是，就必须同改或降级为指针。第二条问句：**这份摘要里有数字或范围吗**（`R1–R14` / `3 条` / `19 行`）？有就当场数一遍。

## A-14 新反例与旧反例同根因（反例册变成同义反复）

- **现象**（本方法仓 2026-10-31 同一册的两处；复核 **R-2** 与 **R-5** 分别抓出）：
  ① **§8.2 R-2**：A-10 首版的根因写的是「两处书写点只改被看见的那处」—— 这正是 **A-06** 的根因。复核判「A-06 的同义改写，违反册首『三个不同根因各一条』」→ **整条换根因**（改成「指针落到另一个物：局部编号被当全局 ID / 一物两名」），实例也重选（重选结果见该记录的「处置」列）。
  ② **§8.3 R-5**：同一册又抓出 A-10 的第 ③ 条实例（「索引区间写短」）其实是**摘要漂移**，不是 A-10 的根因 → **删掉该实例**。
- **根因**（**本条的归因** —— 原记录只记了「A-06 的同义改写」这个结果，没记机制）：册首写了「三个不同根因各一条」，但这句话是**自评**的：作者按**标题**判断「我是不是新根因」（标题不同 → 以为根因不同），而根因是正文里那句结构解释。**缺一个动作** —— 把已有条目的根因句抽出来、逐条问「我这条能不能替换掉它」。没有这个动作，标准只是愿望；而失败**不报错**：两条都读得通，读者读到的是同一件事说了两遍，却以为「这个坑有两个形态」。
- **正解**：**P-21**。**动作**：立条前把已有反例的根因第一句抄成清单，逐条做替换测试；能替换就换根因 / 降为实例 / 降为证据行。**分工**：册首那句「三个不同根因各一条」只是**数量口径**，判「不同」的判据在 P-21 —— 本条是「按标题判重」的病，不是「条数不够」的病。
- **怎么早发现**：写新条前，把已有反例的**根因第一句**抄成一行清单，逐条问「**我这条的根因句能不能替掉它而不失真**？」——能替 = 同根因，不许立条。第二条反向问句：**我这条现象，换一个根因解释能不能也讲通？** 能 → 它是别条的实例。

## A-15 反例引的原文被上游订正（引文自己消失了）

- **现象**（本方法仓 2026-10-31）：
  **R-3**：A-11 的实例 ② 引了上一棒 handoff 的**两行原文**（`cards.partition`）当实测；而上游项目那份 handoff **当天就已就地等长订正**，复核实测该串 **0 命中** → 引文不可复现。处置 = 改为只引那份判定记录的**编号**，并注明「原件已订正、原文不可复现」。
- **根因**：取证时选的是「**最像当时原话**」的形态（引别人文档里的句子），而正文是**活的**：作者可以就地订正、可以搬走、可以被忽略。反例把这份活正文当证据底座，于是在写下的那一刻就埋了一个**会自己消失的引文** —— 条目本身读得通、不报错；下一个复核者才发现「这句话不存在」，而**最坏的形态是他以为自己找错了文件**。**与 A-12 不同**：A-12 是**指不到**（文件 / 节号不存在、换机解析不到）；本条是**指得到、但内容已经被改过**（同一轮复核里那处「跨仓指针被 `.gitignore` 忽略、未标『本机未跟踪』」属 A-12 的面，不是本条）。
- **正解**：**P-24**。**动作**：把引文换成编号 / 记录 / 节标题 / 命令尾行；确需引原文就标「原件可能已被订正」+ `复核月`。**分工**：A-12 是**指不到**（文件 / 节号不存在、换机解析不到）；本条是**指得到、内容已经被改**。跨机可解析性归 `P-18` ③，不归本条。
- **怎么早发现**：每条引文问一句「**下个月还有谁能打开这句话**？」——只有编号 / 记录 / 节标题 / 命令输出能答「是」；答「原作者可能改了它」= 换形态。第二条：引里的**数字**（几行 / 多少处 / 哪个值）当场数一遍（数字只作当时观测）。
