一个子代理 = 一份**独立上下文** + 一条**只能靠提示词传递的任务**。所以难点不是「让它干活」，是**在信息不共享的前提下把边界说清**，以及**事后还找得到它**。

本文件 = 本方法仓对「子代理怎么派」的**唯一书写点**（角色层指针在本方法仓的稳定层件）。出处只作证据（见文末），**正文以本文件为准**。

> **harness 假设**：本文件按**能力**描述，不按工具名 —— 下文出现的 `subagent` / `send_message` / `interrupt_agent` / `read` 等都是**某个 harness 的示例名**。换 harness 时按能力对号（能力清单 = `GUIDE.md` 的「工具能力假设」）。**判断一条规则适不适用，看能力，不看名字。**

## 一、先判：这活该不该外派

满足任一 → 考虑拆：
- 主线程**只需要结论**（调研 / 候选生成 / 大范围扫描）。
- 过程输出会**污染主上下文**（长试错、大量工具结果）。
- 要**综合**消化一份整读不完的材料（`read` 单次上限之上），只要摘要回来。
- 多个**互相独立**的子任务可并行。

命中任一 → **不拆**：
- 与主线程**高频往返、强耦合**（同一热路径连续迭代，需要反复看本会话中间态）。
- **写提示词的成本 ≥ 自己做**（大量隐性决策在本会话上下文里，转述不出来）。
- 结果**无法一句话验收**（回传后你还得重读过程 = 隔离失败）。

## 二、选型

| 用哪个 | 什么时候 |
|---|---|
| **独立上下文**（示例名 `subagent`） | **默认**。判据：这件事我能不能写成一段「别人照做就行」的说明？能 → 用它 |
| **继承本会话**（示例名 `subagent_fork`） | 延续性工作 —— 必须靠本会话已建立的隐性上下文，写成自包含 prompt 会丢关键前因 |

两者都**只回流结论**，过程不自动并入主会话。

## 三、四条硬纪律

1. **可续**：派出去必须拿得到**可持续的句柄**（DSH 示例：`subagent` / `subagent_fork` 返回 `subagentId`，能 `send_message` 追问 / 纠偏 / 续跑）。拿不到句柄的派发 = 一次性消耗品：结论被截断只能重跑，也没法追一句。
2. **复用优先**：派新活之前先查「本会话有没有已派过、还在的件」。能复用就复用（它的上下文还在）。**新开只限三种**：任务性质不同 / 旧件上下文已污染 / `send_message` 明确失败。
3. **复用前先确认余量（[硬]）**：判断「复用还是新开」需要知道旧件的上下文用量 —— **能不能读到，取决于你的 harness**：有工具 / 面板 / 日志就读它们；**读不到就问用户**（附三项：旧件读过什么 / 新活要读什么 / 两者重合度），由他看完余量再定，或直接指名。**别凭感觉复用** —— 两个方向都错：用满会掉质量，够用却新开是浪费。
4. **预算**：单个子代理有上下文上限，而**质量拐点随模型变** —— 上限不等于实用顶。**经验值（示例，不是阈值）**：1M 上下文的模型，有人在 500–600K 之后观察到产出开始不稳；200K 一档的模型拐点更早（过半就该警惕）。**这两个数只是起步参考** —— 以你这条模型的实测为准（`P-13`：一次观测不能写成常量）。所以**先问两件事**：① 你（主会话）的模型上下文多大 ② 子代理是否同一个模型 —— 不一致时按**更小的那个**算。过了拐点就**收口换人**（新件接棒 / 主会话接手）；长任务在提示词里写「收敛 / 预算」。

## 四、提示词里必须有的四块

1. **自包含**：目标 / 边界 / 输入材料路径 / 交付物 / 验收标准 / 不做清单。**禁止**让它回来补问路径。
2. **并发写面**（同一工作树上主会话与 worker 并行时）：写明 ① 主会话会同时改哪些路径 ② worker **独占**哪些。worker 侧两条 —— **a)** 白名单外 / 非独占路径出现变化**属预期**（不处理、不回滚、**不上报、不追问**）；**b)** **禁** `git checkout` / `restore` / `stash` / `reset`（会毁掉并行改动）。判断改动归属一律按路径过滤。
3. **能力提示**：worker 常**低估自己**（例如以为自己是纯文本模型、不能识图）→ 写明可用能力与调用方式（示例：`read_image(<path>)` 接受图像输入、截图工具的 `image` 附件 —— 换成你的 harness 的工具名）；**禁**「凭文件名 / 描述猜图」。
4. **禁写确认回合**：「读完后先向我报告 / 我确认后再做 / 有卡点随时问我」—— 后台**没有这个回合**，写了会让它空等或把正常推进误报成卡点。**做完即停**要显式写（防它回去做上下文里更早的任务）。

## 五、中断 ≠ 作废旧任务（最容易踩）

**中断**（示例名 `interrupt_agent`）只停**当前回合**；它上下文里的**旧任务书仍在**。向被中断的件发新活，它会先答新问、再**回头做旧任务**（实测过）。
给被中断过的件派新活 = **三条硬要求**：① **显式作废旧任务**（「原来的 X 已由主会话收口 / 作废，不要再做」）② **声明这是唯一任务** ③ **做完即停**（「不要继续你上下文里更早的任务书」）。
**优先级**：一次性小任务别用带旧任务书的件 —— 用新件，或**主会话自己验**（往往更省）。

## 六、等与读

- **等待**：派完后，把自己那侧**不依赖它**的事做完就**停**，等运行时通知。**不得**因「等太久」或想赶 commit 而中断或反复催问。中断只用于派错 / 明确阻塞 / 换任务（并按 §五 三条）。
- **依赖它的写回**：复核 / 结论未回之前，**不 commit 依赖它的契约或规则类写回**；若已 commit，反例以 follow-up 修正并登记过程偏差。
- **读回传**：别 `slice` 输出（数组首项常是超长推理，预算被它吃光、结论被丢掉）；取非 reasoning 项全文，长结论**落文件再分页读**。结论被截断且无 id 可取回时，**请用户从 UI 复制贴回**比重跑便宜。

## 七、不固定的东西

**没有「子代理角色表」**。可复用的是**任务型 → 提示词要点**（分流判据 + 能力提示 + 并发写面 + 中断作废），**不是 agent 身份**。
给「收尾件 / 验收件 / 真机件」固定一个专职子代理，会和「复用优先」直接打架（一条要求必须新开、一条要求优先复用），也会把主会话职责固化出去 —— **收尾同步 / 独立复跑门禁本来就是主会话的活**。

## 八、与「强复核」的边界（常被写错）

**强复核子代理**另受收尾清单第 1 步的派发前置约束（用户授权收尾 + 写回面五件落盘）。
**普通干活子代理不受此限** —— 「缺前置就不许派子代理」是错的写法：它只约束**强复核**。

## 九、怎么造一个「干净测试场」（盲测 / 陌生人测试用）

工作区说明（`AGENTS.md` / `CLAUDE.md`）通常由 harness 的**注入机制**提供（DSH 示例：`dsh-agent-instructions`），链路 = **用户全局链** → **项目链（从项目根到会话工作目录）**。实测（2026-10-31，DSH）：

- **子会话的链从它自己的 cwd 算起**，不继承父会话的壳；cwd 是空目录时，它只拿到那条 prompt。
- 本机全局链为空（`$DSH_HOME` 与用户主目录、盘根均无 `AGENTS.md` / `CLAUDE.md`）→ 没有隐式污染源。
- **风险点**：包文档说「`read` / `write` / `edit` 触及更深目录后，**下一次请求**并入新链」→ 被测者一旦读了方法论仓里的文件，后续回合可能被并入那边的 `CLAUDE.md`。**此条未实测**（按最坏假设办）。

造测试场三条硬规则：

1. **目标目录里不放 `AGENTS.md` / `CLAUDE.md`** —— 放了就是给它开卷。
2. **不让被测者读仓外文件**：把要给它看的资料**拷进测试目录**或内联进 prompt，别让它去读真仓。
3. 要绝对隔离就用**新工作区**（GUI 新建，root = 空目录）：那条会话没有父上下文、没有任何注入块，报告里会明确写「全程无 `Instructions from:` 块」。

**别把「派了子代理」当成「陌生人测试」**：子代理仍是你的子代理（你给的 prompt 就是它全部题面）；新工作区里那条会话连你的存在都不知道。

## 十、怎么读「盲测 / 陌生人测试」的记录（不听自述，看动作序列）

判读的唯一材料 = **harness 自己的会话记录**，不是被读者的总结。**落点因 harness 而异**（示例：Claude Code 在 `~/.claude/projects/<工作目录路径编码后的目录名>/*.jsonl`，一次会话一份；DSH 在它自己的会话侧）—— 先确认你这一侧去哪读；**读不到就只能退回「自报合规」并标明**（`P-19` 不假装有证据）。删掉测试夹具**不影响**会话记录。

**四样必统计**（每样都能一条命令出数，别凭印象）：

1. **首读是哪个文件** —— 决定「第一屏对不对」。
2. **工具调用序列与次数**（按工具名分组）—— 决定它是按协议走，还是自己发明了流程。
3. **工作区外读取次数** —— **污染面**。> 0 就要追：它读到了什么？读了出题人的仓（记录区 / 交接区）= 本次样本**作废**，不能当「陌生人可用」的证据（`P-19`）。
4. **写入清单** —— 几个文件、走 Write/Edit 还是 Bash 复制。**Bash 复制不会出现在 Write 列表里**，只看 Write 会低估它写了什么。

**判读四条**：

- 它说「我读了 A」不算 —— 要有 Read 调用指向 A。
- 它自评「我做得对不对」不算 —— 自评只作待验清单（`P-19`）；拿它的**动作**与协议原文对差。
- **别写死数字**：本方法仓第一次这么做时记过「278 行 / thinking 28 / Read 40 / Bash 12 / Write 12」—— 那是**一次观测**，写进文档就过期（`P-13`）。要写就写口径 + 出处日期。
- **它的归因也是自述**：说「工具没给我 X」时，去会话记录里看那次工具到底返回了什么 —— 认错对、归因错，会把「读法不对」误诊成「工具坏了」。（实测：某场说读回来的内容没有行号，记录里那次的返回是带行号的。）

**与 §九 的分工**：§九 造场（别让它开卷），§十 判读（别让它自评分）。两者都省了，「陌生人测试」就退化成「我的子代理说它行」。
