# L0 原则 · 02 收尾（真源闭合 / 不可延后 / 分流 / 反查 / 可证伪）

> 本册 = 「一次会话结束时，用最少的动作让下一次会话不需要追问」。条目：`P-06`..`P-10` · `P-31`。
> **阈值不写在本册**（真源 = `kit.config.json`）；**动作清单也不写在本册**（发布件按 `kit/templates/CLOSEOUT.md.template` 自建；维护者仓见 `WORKFLOW.md` §收尾）。本册只写判据。
> 术语先分清：**分流**（写入那一刻定去向：过程账 → 历史区）≠ **归档**（把已收口的整段当前区搬走；常态等收口、撞线可应急）。两者触发条件不同，见 P-08。
> 每条四段：**规则** / **为什么** / **反例** / **怎么查**；`怎么查` 没有机械点就诚实写「半机械」，不假装有门禁。

## P-06 收尾的完成标准 = 真源闭合，不是「跑完了」


- **规则**：收尾做没做完，只问四句话：① **状态真源**（版本 / 进度 / 当前第一读）改了吗，且只在一处写全？② 本轮改了**判据 / 契约**吗（照着做的人的动作会不会变）？③ 出现**新坑 / 新留后项**吗，有编号 + 登记面吗，**到期的复审了吗**（P-07）？④ 改了名或换了落点吗，**旧名还在吗**（P-09）？
- **判据**：「**下一个会话不追问就能重建它**」—— 状态类事实要求**第一屏上有指得通的指针**（数值本身不写在那里：单一书写 + 字节门）；新坑 / 留后 / 契约按各自登记面的指针找得到即可。**指针断了 = 等于没写。**
- **为什么**：收尾是唯一**没有下一个人替你做**的动作 —— 没写回的东西不会「以后补」，会变成「没人知道它存在」。成本也不对称：现在几分钟，下一会话要重新发现一遍，而且**发现的人不知道自己丢了东西**（A-04 / A-05）。
- **怎么选模式**：会话末 / 有人喊收尾 → **全量**；会话还在继续 → 只有「就地四类」（后续项要读本次改的真源 / 动了规则协议文件 / 契约变更 / 项或阶段收口）就地做，其余攒到会话末。**不可延后五类在任何模式下都就地**（P-07）。
- **反例**：A-04（三处版本各说各的，而门禁全绿）。
- **怎么查**：**半机械** —— 版本只有一处被探针 6 覆盖（`VERSION` ↔ `CHANGELOG` 顶部）；**状态行 / 第一读 / 留后项 / 到期复审没有任何探针**，靠 `kit/templates/CLOSEOUT.md.template` 第 2 步逐项勾。

## P-07 不可延后五类：「以后写」等于「丢掉」


- **规则**：五类**当场落盘，与本轮改动大小、与会话是否结束都无关**：① 契约冻结 / 变更 ② 用户原话 / 拍板 ③ 新坑（编号顺延）④ 状态真源 + 旧名 / 节号迁移 ⑤ 新开放项 / 留后（进**唯一登记面** + 到期触发）。判据只有一句：**如果这一轮现在结束，下一个人还重建得出来吗？** 重建不出 → 现在写。
- **留后复审（每次收尾必做）**：第⑤类不是「记下来就完事」—— 扫一遍登记面里的**到期项**，逐条给处置：**清 / 续期（写理由 + 新触发）/ 拍板 / 维持**。到期未清**阻断下一次收口**，否则登记面就是墓场。
- **为什么**：批模式省的是「复核 / 汇报 / 归档」的 wall-clock，**不省这五类** —— 它们是不可逆信息，延后不产生节省，只产生丢失概率；而丢了**不报错**（A-05：一条留后项搬一次家就没了，全仓 grep 0 命中）。
- **反例**：A-05。
- **怎么查**：**半机械** —— 「**编号是否顺延**」**没有探针**（探针 2 只查被引用的 ID 存在，查不出跳号 / 复用 / 不重排）；**留后项别靠 token grep**（标记形态随项目变：登记面的**表行**通常不带 `｜OPEN` 这类标记（该 token 可能只出现在表外一句转述里，拿它 grep 命中的是**别人的口径**，不是你的留后项））—— 要**打开登记面逐条看**；「用户原话」无门禁，靠收尾汇报**逐字引用 + 日期**（P-10 ⑤）。

## P-08 写入即分流：过程账进历史区，归档只认两个触发


- **规则**：两个动作分开看。**分流**：常态写入只写「状态行 + 结论 + 指针」，过程账与原始证据**当场**进历史区（原文逐字、机械搬运、不手写 / 不 LLM 重写），并同步索引；教训**转正**为规则后，原条目压成一行 + 指针。**归档**：把已收口的整段当前区搬走 —— **常态只由棒 / 批次 / 真机窗口收口触发**，不是「项 / 阶段」。搬运**必须**：搬前列清单 → **展示给用户确认** → 搬 → 搬后再列 → **两边数条数**（上游项目口径：[硬] 绝不默默执行）。
- **两个归档触发，不许互替**：① **收口**（常态，本条）② **容量撞门**（应急：冷启动三件的字节门顶到强制归档线就搬，判据与动作由 **P-01** 定义，不等收口）。反过来，分流做得好也不等于冷启动不会超支。
- **为什么**：累积类文档是唯一会无限增长的一类；「等它长大再搬」要先把已收口的部分从没收口的部分里分出来，那一天得先写脚本（A-02 的 246.7 KB 就是这么长出来的）。**写入时决定去向，是唯一零成本的时刻。**
- **反例**：A-05（搬运没有前后清单 → 丢条目不报错）/ A-02（不分流 → 无硬顶的查询型文档）。
- **怎么查**：**只有容量面可机械查** —— 探针 3 / 8 / 10 查分档与上限（P-03 / P-05 的机械点）；探针 7 查的是**按节读声明**（属 P-04，不是本条）。**「归档触发是否成立」「当前区 / 历史区边界」没有任何探针** → 半机械，靠 `kit/templates/CLOSEOUT.md.template` 的归档判断项（**第一问 = 先判触发**）人工卡。

## P-09 改完要反查：枚举形态、扫全集、逐条裁决


- **规则**：触发面**四类** —— 名字 / 路径 · 节号 · 状态词 · 关键数字。改了任一类就必须反查，且三条同时满足：
  ① **枚举形态**：名字 / 路径类枚举**三形**（全名 / 目录前缀 / 旧措辞）；节号 / 状态词 / 数字类**没有目录前缀形**，改成枚举「文档里可能怎么写」（如 `§4.8` / `§4` / 「第四节」）。
  ② **扫描面 = 查询得到的全集**（活文档 + 抽屉 + 归档），不是「你觉得会怎么写」。
  ③ 每条命中**落一个判定**（改指 / 历史件豁免 + 理由 / 别名承接），**不许留白**。
  多书写点的状态词，必须全仓 grep **所有书写点**。
- **为什么**：改名的人是在**自己正在看的那一处**改的，其余靠记忆 —— 而记忆不知道自己漏了哪里（A-06：两处书写点只改了头部）。漏掉的反查不会让任何门禁变红，只会让下一个人**按错的东西做事**。
- **反例**：A-06。
- **怎么查**：**半机械** —— 本方法仓路径死链由探针 5 查、交叉引用由探针 2 查；**但「旧名是否还有残留」没有探针**（探针只认格式，不认旧语义）。手工等价：`git grep -n -F "<旧名>"` + 抽屉 `--untracked --no-exclude-standard`。

## P-10 结论必须可证伪：数字贴尾行，复核换判据


- **规则**：① 文档里的**可测量数字**（字节 / 行数 / 条数 / 用例数 / 编号 / 版本）在**最后一次编辑之后**重测，并以**命令尾行**贴出 —— 修辞性数量（「几分钟 vs 半小时」）不在此列。② 第二遍复核**换判据**：只找反例、走独立通道，产出 = **反例清单 + 覆盖范围**（0 条也要写「查了哪几类」）；**弱档可跳过**（纯追加 / 单文件小改 / 纯指针更新），但必须写「跳过 + 理由」。③ 禁止「检查了，没问题」这类**不可证伪**结论。④ 复核反例里**机械类（字符串 / 指针 / 数字）占一半 = 自查失职**：先补机械自查，不许收紧复核；**假阳性多 = 触发过宽**，也应收紧触发而不是加码复核（本册不复述）。⑤ 汇报：给不熟悉本行的读者**一句话人话结论，放在所有数字之前**；本轮凡含用户拍板 / 口径原话，**逐字引用 + 日期**。
- **为什么**：门禁只证明「当轮绿」，不证明「会咬」；文档里的数字一旦不是命令输出，就等于**把一次性的观测当成长期承诺**（P-13）。而复核若只是「再看一遍同一份清单」，它查的仍是**那份清单之外的未知** —— 第二遍换判据才有信息增量。
- **反例**：A-06（汇报写「9 条指针」，清单里实为 8 行：数是数出来的，不是命令输出）。
- **怎么查**：**半机械** —— 机械点 = `node kit/scripts/check-kit.mjs`（引用 / 死链 / 单行长度）+ `node kit/scripts/selftest.mjs`。**注意层级**：整套 selftest 全绿只证明「整套里有探针会咬」，**不证明新增的那一条会咬** —— 新探针必须配一个**只有它能红的独立注入态**（红 → 复原 → 绿），并在汇报里贴那次红的尾行。另：「数字是否重测过」「复核是否换了判据」没有门禁。
## P-31 去重 = 迁移 + 至少一条可达指针（禁止「删掉就没」）


- **规则**：合并 / 归档 / 瘦身时，**被删掉的内容必须在原处留一条能走到的指针**（指向新址，或明写「已删，原址 = …」）；删之前做**双向指针审计**：① **出向**（上游项目口径）—— 被删段**引用的每个真源**在新址仍要能到达，别让「删掉这段」把它带走了；② **入向** —— 全仓（活文档 + 抽屉 + 归档）grep 旧路径与旧标题，命中处逐条裁决（改址 / 加指针 / 明确标注）。**不适用**：删的是**从未被引用**的草稿 / 临时件 —— 判据 = 改前 grep 旧名 **排除被删文件自身**后 **0 命中**，且它不在任何索引 / 地图 / 台账里（跨仓搬迁时**两边都要查**）。
- **为什么**：删完文档更短、结构更干净，而**失败不报警**：「指向不存在的东西」与「指向正确的东西」在文本上一模一样；只有下一个真去点的人才会发现，而那时他已经不知道该找什么了（`P-09` 只保「旧名有没有残留」，保不了「被删的那段有没有人指过」）。
- **反例**：`A-20`（归档搬段时，**指向旧归档的那一行恰好落在被搬的段里** → 主文件里再也找不到旧归档，grep 0 命中）。**与 `A-05` 的分界**（`P-21` 替换测试）：`A-05` = 搬运**丢内容**（数条数能抓，`P-07`/`P-08` 管）；本条 = 内容没了或挪了位置、**指针不再可达**（grep 指针能抓）—— 留指针救不了漏抄的条目，数条数也救不了断掉的指针。
- **怎么查**：**半机械** —— ① 删前对每个被删标题 / 路径跑全仓 grep（活文档 / 抽屉 / 归档各几命中，逐条裁决）；② 删后跑 `node kit/scripts/check-kit.mjs`：探针 5 只认**带 `/` 的 `.md` 路径**，**认不出「被删的标题文字」** —— 所以第 ① 步不能由门禁代替（`P-15`）。
